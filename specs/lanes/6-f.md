Mechanical fixture fix, no behavior or type change — not a judgment call, so fixed inline rather than reported and left red.

## Assumptions

- Two path-filtered workflows (not one combined) mirrors `../multip`'s working pattern and keeps a frontend-only change from rebuilding the backend image.
- Docker build step duplicates work the app's own multi-stage Dockerfile already does (typecheck happens twice: once bare, once inside the Docker build). Left as-is — matches `../multip`'s CI, and the bare run fails faster/cheaper before paying for a Docker build.

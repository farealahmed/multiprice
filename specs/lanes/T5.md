# Lane T5 — Editor UI

## What landed

The line-item editor from `design/htmls/document-edit.html`, wired to T4's `preview()`:

- **`app/(app)/editor/page.tsx`** — client page (Topbar + `.page` pattern from `app/page.tsx`).
  Owns row state (`RowState`: raw input strings, local `key`, local-only `description` — A7),
  fires `preview(toLineInputs(rows))` on every edit, and tracks one honest `pending` flag:
  true whenever the numbers on screen are not the server's answer to the inputs on screen
  (debounced, in flight, mid-edit, or last rejected). No save/finalize/metadata (ARCH Out of
  Scope). No shell changes — nav wiring is T6's.
- **`components/line-items/`** — `LineItemsTable` (11 columns per mockup), `LineItemRow`
  (inputs + 4 server-result cells, positional match A7, inline `role="alert"` field errors),
  `DiscountInput` (thin controlled type-select: value input exists only for the selected type
  and switching clears it — "both at once" unrepresentable, R10), `DocumentTotals`
  (subtotal / −discount / +tax / grand, `$` prefixes, em-dash placeholders before the first
  response), `error-mapping.ts` (`details[].path` → row/field, unmatched → document level),
  `row-state.ts` (input parsing; incomplete input fires no request), one CSS module ported
  from `styles.css` against `styles/tokens.css` variables.
- **`components/money/`** — `formatMoney` (the single money→text path: 2dp, no grouping,
  `Intl.NumberFormat`) + `Money` display component (tabular numerals). No arithmetic anywhere
  in the footprint: grep-verified no `useMemo`, no `toFixed`, no `*`/`+` over money (only
  `index + 1` row numbering).

## Evidence caveats

- Screenshots come from a static HTML capture of the **real components** rendered in jsdom
  (lanes may not boot port 3000) with the real globals/tokens/module CSS. Two artifacts:
  `<select>` elements show their first option (jsdom `innerHTML` drops the runtime `value`
  property — select behavior is covered by the component test instead), and Google fonts fall
  back to system serif/sans. Pixel-level confirmation against the live stack is T6's Cypress
  happy path — T3's route did not exist yet when this ran, so no live round trip was possible
  from this lane.
- Verified in headless Chromium at 1400×900 only.

## For the join

- **vitest cannot render `.tsx` project-wide**: `tsconfig` has `jsx: preserve` and
  `vitest.config.ts` doesn't set esbuild's JSX mode, so any component test that imports a file
  without my pragma (e.g. everything in `components/shell/`) dies with `React is not defined`.
  T5 worked around it in-slice (pragmas + a `Topbar` module mock in the page test). Recommend
  the one-line fix `esbuild: { jsx: 'automatic' }` in `apps/frontend/vitest.config.ts` (outside
  T5's footprint); the pragmas stay harmless either way.
- `vitest.config.ts` has `globals: false`, so Testing Library's auto-cleanup doesn't run —
  component tests must call `cleanup()` themselves (mine does).
- The editor page is at `/editor`, ready for the nav entry (T6). Page title/heading:
  "Line items editor", kicker "Document · live preview".
